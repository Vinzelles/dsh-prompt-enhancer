# ADR-0002:子代理身份契约随宿主动态解析 — 双代宿主(0.1.1/0.1.2+)兼容

- 状态:已接受
- 日期:2026-09-07

## 背景

插件在创建强化子会话(通道 B)时,必须在创建窗口内补写一条 `subagent/descriptor` 会话事件——这是宿主 dsh-subagent 子代理目录(list-children)折叠子会话身份的唯一依据。缺失或版本不匹配时,宿主把该子会话判为 `diagnostic/corrupt`,UI 显示「会话记录损坏」。

宿主升级改写了这个契约的版本号(经 npm 发布物逐一实证):

| dsh-subagent 版本 | SUBAGENT_DESCRIPTOR_VERSION |
| --- | --- |
| 0.1.0-rc.8 ~ 0.1.1-rc.2 | 2 |
| 0.1.2-alpha.2 ~ 0.1.2-rc.1(当前) | 3 |

两代宿主的 `foldSubagentDescriptor` 语义完全一致:`version !== 当前值 → undefined`(无身份 → corrupt)。one-shot 字段集(`version/mode/provider/label`)在两代间逐字相同——差异仅在版本数字。

事故:宿主 0.1.2 发布后,插件硬编码的 `version: 2` 被折叠为无身份,「强化」的子会话全部显示损坏(2026-09-07 诊断日志实证)。反向陷阱同样存在:若简单改成硬编码 3,公开发布后 0.1.1 宿主用户全体损坏。

## 决策

descriptor 版本**永不写死**,模块加载时从宿主依赖树 `@deepseek-ai/dsh-subagent` 解析真实契约,三级通道依次兜底:

1. **import 读常量**(首选):动态 `import()` 宿主包 `lib/types/descriptor.js`,读 `SUBAGENT_DESCRIPTOR_VERSION`——与宿主同一份运行时事实,不受 profile 树残留旧包误导。
2. **文件正则扫描**:import 抛错(宿主包自身依赖异常等)时,直读同一文件扫 `SUBAGENT_DESCRIPTOR_VERSION = (\d+)`。
3. **包 semver 推断**:常量不可见(宿主改版挪走文件/常量名)时,读包 `package.json` 版本按实证边界映射:`< 0.1.2 → 2`,`≥ 0.1.2 → 3`。

三通道全失败(宿主包整体定位不到)才用最终兜底 3(最新契约)——此时本宿主根本没有消费 descriptor 的子代理目录,损坏判定无从发生,兜底值只为前向安全。诊断日志 `descriptor-version-resolved` 记录 version 与 channel,漂移可取证。

## 后果

- 正面:0.1.1(v2)与 0.1.2+(v3)用户同时受保护;宿主未来再 bump 版本时通道①②自动跟随,仅「新增必填字段/挪走常量」这类破坏性改版需要插件改动(测试锚点会先变红示警)。
- 代价:解析链三级兜底带来少量复杂度;semver 边界(0.1.2)是本次实证快照,若宿主回溯发版会失真——由「兜底匹配宿主常量」回归测试与 diag channel 信标兜住可观测性。
- 约束:0.1.1 兼容定位为**过渡支持**(README「宿主兼容」明示),后续版本将逐渐弃用;弃用时本 ADR 追加修订记录,不悄悄删通道。

## 替代方案(否决)

- 硬编码版本 + 「按宿主版本分支」:每次宿主 bump 都要发新版,公开插件不可接受。
- 不写 descriptor、让宿主官方驱动补:本插件不走官方 subagent seam(需要创建窗口内即写、且子会话可能被取消/无文本),官方 in-process driver 的 pre-step 追加时机覆盖不了失败路径(创建窗口内的取消/无文本场景同样需要身份)。
- 只兜底 2 或只兜底 3:总有一代宿主全体损坏,即本 bug 的两个方向。
